Users Collection
All users signing up to the website will need to fill out a form to actually use the website. even if they registered with google, an email is required. The information inputted into the form will be stored as a document in the firestore in the collection Users. At the same time of creation. fields should be email-preferred, email-login, username, name-first, name-last, pronouns={object:"", subject=""}, phone, ucid, major, year, isPaid=boolean true or false if the user has paid their fees, isExecutive=true or false if the user is an executive (this is important for verifying access to the executive portal), isRegistered=true or false has the user finished registering, isUCDS=true or false this user is eligible to be a part of the UCDS (university of calgary student). isRestricted=true or false is the user has restricted access to app functionalities. type=["a list of things the user is considered as"]. Make sure that when a user deletes their account, their entry in Users is also removed. The name of the document should be the exact same as the indentifier in the authentication for firebase. 

Subscribers Collection
the Subscribers collection is used for mailing lists. documents in this collection can have the fields; email: "" (email stored as string), name-first: "" (first name stored as string), name-last: "" (last name stored as string), lists=["list of mailing lists that the user is subscribed to"], isUser=boolean true or false based on whether if the subscriber has an associated account with the app/website. The name of the documents should be the email.

Organizations Collection
the Organizations collection is a directory for the information about debate-related organizations globally. the name of the documents in this collection should all be the name of the club with spaces replaced with hyphens and capitalization, numbers and symbols removed. Fields of the documents should include: type=["what kind of organizations this organization is. for example, club, authority etc."], formats=["list of formats the club participates in"], name="name of the club", name-abbreviation="abbreviated name of the organization", name-affiliated="the name of the organization's affiliated institution (university usually)", location={"country":"country name", "city":"city name" etc. map of strings}, email="the main contact email for the club", links={"name":"link"}, executives={(role with hyphens and no capitalization)={email="", name-first="", name-last=""}} This is a nested map of executives information for the club, time-updated, time-created. Please follow the example that can be found listed as _default. Make sure _default does not appear on the webapp.

Safety and Resource Optimization:
to decrease the amount of reads, make sure that that the client-side and server-side aren't constantly updating. Try to save server-side resources. this goes for everything on the website. Try to hold as much data on the client-side before needing to request or send new information.
